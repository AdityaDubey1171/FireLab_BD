Firewall Security Laboratory

A firewall acts as a security control between a trusted system and potentially untrusted network traffic. It examines traffic, compares it with security rules and decides whether the traffic should be allowed or blocked.

This laboratory demonstrates that decision-making process safely. No real attack traffic is generated and no external system is scanned or attacked.

Open the simulator How firewalls work

How does a firewall protect a system?

A firewall controls network traffic entering or leaving a protected system, following predefined security policies. Select a card to read more.

What it is

A mechanism that controls network traffic entering or leaving a protected system or network.

How it works

Traffic reaches the firewall, which examines information about the request and compares it against its configured rules.

What the firewall does

If the traffic matches a rule that says BLOCK, the simulated firewall rejects it. If no malicious rule is matched, the traffic is ALLOWED according to the demonstration policy.

Why it matters

Without a firewall, every request could reach the application directly.

What it is

A set of properties the firewall inspects on every request.

How it works

The firewall looks at the traffic source, the destination or service, the protocol and request characteristics, then applies security rules and a threat classification.

What the firewall does

It combines these checks into a single decision: allow or block.

Why it matters

Checking several properties makes it harder for harmful traffic to pass as normal.

Firewall decision process

Every simulated request follows the same six steps. After you run a simulation, the steps below show the outcome.

What it is

The simulated attack type you enter in the form.

How it works

The request is sent to the firewall instead of directly to the application.

What the firewall does

Receives the request and starts inspection.

Why it matters

All traffic must pass the same checkpoint.

What it is

Examination of the request's source, target and characteristics.

How it works

The firewall reads the simulated request details.

What the firewall does

Prepares the information needed for rule matching.

Why it matters

Good decisions need accurate information about the traffic.

What it is

Matching the request against the firewall rule set.

How it works

The attack type is looked up in the defined security rules.

What the firewall does

Finds a matching rule, or finds none.

Why it matters

Rules are the policy that tells the firewall what to do.

What it is

Assigning a category and severity to a matched threat.

How it works

A matching rule provides the category and severity.

What the firewall does

Marks the request as a known threat or as normal traffic.

Why it matters

Severity helps administrators prioritise what they review.

What it is

The firewall's final decision.

How it works

A matched block rule results in BLOCKED. Otherwise the demonstration policy allows the traffic.

What the firewall does

Stops the request before it reaches the protected system, or lets it continue.

Why it matters

This is the step that actually protects the application.

What it is

A saved record of the decision.

How it works

The event is stored in the project's security database.

What the firewall does

Keeps the record so it can be reviewed later.

Why it matters

Logs support investigation, auditing and reporting.

⚠️

Educational security simulation. This laboratory demonstrates firewall decision-making using predefined rules. It does not generate real DDoS traffic, perform real port scanning, execute SQL injection, execute JavaScript against another system, access unauthorized files, or attack external systems. The "BLOCKED" result represents the simulated firewall decision and demonstrates how a security control can stop a known threat before it reaches a protected application.
